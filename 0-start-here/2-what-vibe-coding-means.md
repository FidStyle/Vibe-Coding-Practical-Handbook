# 0.2 本手册里的 Vibe Coding 是什么

在这本手册里，Vibe Coding 不是“输入一句话，AI 自动写完”。那只是最浅的一层，而且很容易把人带到错误习惯里。

本手册里的 Vibe Coding 是：

> 开发者用自然语言、项目文档、工具接口和验证机制指挥 AI Agent，在真实代码仓库里完成可审查、可验证、可恢复的软件开发任务。

## 三个层次

| 层次 | 特征 | 风险 |
|---|---|---|
| 对话式生成 | 在网页里让 AI 写代码片段 | 上下文不完整，难验证 |
| 本地 Agent 开发 | 让 AI 读本地仓库、改文件、跑测试 | 需要控制范围和权限 |
| 工程化 Vibe Coding | 用规范、任务、MCP、skills、harness 管理 AI | 需要维护流程资产 |

很多人停在第一层和第二层之间：能让 AI 写代码，但还不能让 AI 稳定完成真实任务。

## Vibe Coding 不是低质量借口

错误理解：

```text
AI 写得快，所以可以少设计、少测试、少审查。
```

正确理解：

```text
AI 写得快，所以更需要边界、验证和审查。
```

AI 会放大你的表达能力，也会放大需求、上下文和验证里的缺口。需求模糊、上下文错误、验证缺失时，模型越强，错误传播越快。

## 和传统编程的关系

传统能力仍然重要：

- 你需要知道什么是合理架构。
- 你需要知道测试覆盖是否足够。
- 你需要知道安全边界在哪里。
- 你需要知道一段代码是否只是“看起来能跑”。

Vibe Coding 改变的是劳动分配，不是质量标准。

## 本手册的核心立场

```text
Prompt 是入口。
Context 是燃料。
Agent 是执行者。
MCP / skills 是工具和流程扩展。
Harness 是任务边界、验证、恢复和记忆的组合。
开发者是负责人。
```

把这几个角色分清楚，AI 编程才会从一次次试运气，变成可以复盘、可以交接、可以改进的工作流。
