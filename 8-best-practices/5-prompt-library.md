# 8.5 跨阶段提示词库

> 读完本节后，你会有一组可以按任务改写使用的 `Codex`、`Claude Code` 和 `OpenCode` 提示词。

这个提示词库覆盖只读分析、计划确认、diff 审查、文档同步和任务收尾。它面向日常执行；如果你刚开始学习本地 Agent，先用 [3.6 本地 Agent 任务模板](../3-local-agents/6-prompt-templates.md) 跑通第一轮。

提示词库不是用于整段复制的。它的价值在于稳定关键流程；使用前要把占位符改成当前任务的具体文件、命令和验收标准。

## 只读分析

```text
先不要修改文件。

请阅读与这个任务相关的代码、测试和项目规范，然后输出：
1. 相关文件和它们的作用。
2. 现有实现模式。
3. 可能需要修改的文件。
4. 风险和不确定点。
5. 建议的验证命令。

任务：
[写任务]
```

不熟悉本地仓库、多文件任务、bug 定位、重构前分析，都适合先用这一段。

## 计划确认

```text
请先给实现计划，不要修改文件。

计划必须包含：
- 文件范围。
- 每个文件为什么要改。
- 分步骤实施顺序。
- 是否需要新增或更新测试。
- 验证命令。
- Out of Scope。
- 需要我确认的决策。
```

改动超过 20 行、影响公共接口，或者存在多种实现方案时，先让 Agent 交计划。

## 最小实现

```text
按已确认计划实施。

要求：
- 保持最小改动。
- 复用项目已有模式。
- 不要重构无关代码。
- 不要引入新依赖，除非先说明理由并等待确认。
- 不要覆盖或回滚无关用户改动。
```

## 测试失败分析

```text
测试失败了。先不要修改文件。

请分析失败日志：
- 哪个命令失败。
- 哪个测试或检查失败。
- 失败断言或错误是什么。
- 是否和本次改动有关。
- 最可能根因。
- 最小修复计划。

日志：
[粘贴完整日志]
```

## Diff 审查

```text
请审查当前 diff。

Findings first，按严重程度排序。
重点检查：
- 逻辑 bug。
- 无关改动。
- 测试缺失。
- 类型和边界情况。
- 安全风险。
- 文档是否需要同步。

不要总结优点。没有发现问题就明确说没有 findings，并说明残留风险。
```

## 文档同步检查

```text
请检查本次 diff 是否需要同步更新文档。

重点看：
- 命令是否变化。
- 目录结构是否变化。
- 公共 API 是否变化。
- 配置项是否变化。
- 用户可见行为是否变化。
- Agent 规则是否需要更新。

如果需要，只做最小文档更新。
```

## 长任务恢复

```text
请先不要修改文件。

请读取任务目录和当前 diff，然后输出恢复摘要：
- 原始目标。
- 已完成内容。
- 当前阻塞。
- 当前 diff 风险。
- 下一步只做哪一件事。
- 需要运行的验证命令。
```

## 让 Agent 写 PRD

```text
请根据下面的想法写一份轻量 PRD。

要求包含：
- Goal。
- User Value。
- Requirements。
- Out of Scope。
- Acceptance Criteria。
- Risks。
- Open Questions。

不要写实现代码。

想法：
[粘贴想法]
```

## 让 Agent 生成交接卡

```text
请把下面内容整理成给本地 coding agent 使用的 Task Handoff。

输出：
- Goal
- Current Understanding
- Context Pointers
- Constraints
- Out of Scope
- Done When
- Verification
- Risks

不要假设 Agent 已经知道我的仓库。
```

## MCP 使用提示

```text
请使用文档 MCP 查询当前版本的推荐写法。

限制：
- 只查询和本任务相关的 API。
- 总结关键约束，不要粘贴长文档。
- 然后结合本项目现有代码给出实现计划。
```

## skill 创建提示

```text
我已经多次重复下面这个流程。请帮我把它整理成一个 skill 草案。

要求：
- 给出 name 和 description。
- 写清楚 When to Use。
- 写清楚 Workflow。
- 固定 Output Format。
- 写清楚 Rules 和禁止行为。
- 不要包含当前任务特有细节。

重复流程：
[粘贴流程]
```

## 结束会话提示

```text
请做本次任务收尾：
- 总结完成内容。
- 列出修改文件。
- 列出已运行验证和结果。
- 列出未运行验证及原因。
- 检查是否需要文档同步。
- 给出下一步建议。
- 如果这是长任务，生成 Resume Summary。
```

## 使用原则

- 不要一次粘 10 个模板。
- 每次只用当前阶段需要的模板。
- 模板里的占位符必须改成具体任务。
- 如果 Agent 输出过于笼统，要求它绑定文件、命令、diff。
