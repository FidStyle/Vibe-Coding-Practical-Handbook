# 1.1 网页对话的能力边界

网页对话不是低级工具，它适合放在工作流前半段：澄清问题、比较方案、整理材料。到了读仓库、改文件、跑验证这一步，就该切到本地 Agent。

## 适合用网页对话的任务

| 任务 | 为什么适合 |
|---|---|
| 概念解释 | 不需要真实本地仓库 |
| 技术方案比较 | 需要发散和权衡 |
| PRD 草稿 | 需要结构化表达 |
| 错误日志解释 | 先判断方向 |
| 小段代码讨论 | 上下文少，容易复制 |
| 学习资料总结 | 浏览器入口低摩擦 |

## 不适合用网页对话的任务

| 任务 | 问题 |
|---|---|
| 多文件真实修改 | 模型看不到完整仓库 |
| 长任务执行 | 状态容易丢 |
| 跑测试和构建 | 网页端无法直接验证 |
| Git diff 审查 | 复制粘贴成本高 |
| 项目规范执行 | 规范容易遗漏 |
| 需要外部系统 | 手动复制上下文不稳定 |

## 典型错误

错误做法：

```text
把多份文件复制到网页模型里，让它生成完整补丁。
```

问题：

- 你很难保证上下文完整。
- 模型不知道你的文件系统当前状态。
- 生成的 patch 可能和实际代码不匹配。
- 修改后还要手动跑测试。

更稳的分工：

```text
网页模型：帮我澄清需求和验收标准。
本地 Agent：在真实本地仓库里读代码、写计划、改文件、跑测试。
```

## 退出网页对话的信号

出现下面任意信号，就应切到本地 Agent：

- 需要引用 3 个以上文件。
- 需要运行命令。
- 需要看实际 diff。
- 需要遵守项目里的规范文件。
- 任务会持续超过 20 分钟。
- 你开始频繁复制粘贴代码和报错。

网页对话的结束点，是本地任务的起点。好的网页对话最后应该产出任务卡，而不是产出一大段无法直接应用的补丁。
