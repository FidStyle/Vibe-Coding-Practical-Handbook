# 7. 实战路径

第 7 章提供四条练习路径：Web、自动化、工作流工具、Bug 修复与重构。

它们是并列方向，不是考试清单。选择一条与当前能力和目标最接近的路径完整跑通，比每条都只做表层尝试更有用。

## 本章结构

| 子章节 | 目标 |
|---|---|
| [1-web-project.md](1-web-project.md) | 用本地 Agent 做一个 Web 功能 |
| [2-automation-project.md](2-automation-project.md) | 用本地 Agent 做自动化脚本 |
| [3-workflow-project.md](3-workflow-project.md) | 做一个小型工作流工具 |
| [4-bugfix-refactor.md](4-bugfix-refactor.md) | 练习 bug 修复和重构 |
| [5-30-day-route.md](5-30-day-route.md) | 从上手到独立开发的 30 天路线 |

## 本章阅读方式

```text
选一个项目方向作为主线。
用 30 天路线控制节奏。
每个练习都必须走调研 -> 计划 -> 实现 -> 验证 -> 审查。
```

练习结束时不要只看“功能有没有出来”。还要看任务卡、计划、验证记录、diff 说明和复盘是否能让下一次任务少解释一点。

## 读完要学会什么

| 产物 | 用途 |
|---|---|
| 一条练习主线 | 选择 Web、自动化、工作流工具或 bugfix/refactor |
| 项目任务卡 | 把练习目标、非目标、验收标准写清 |
| 验证记录 | 证明功能、脚本或修复结果可检查 |
| 复盘条目 | 把重复问题写回文档、规则或 skill |

## 本章边界

本章提供练习路线，不要求同时完成所有方向。执行细节查 [8. 实用做法](../8-best-practices/index.md)，练完后用 [9. 可验证、可复用、可恢复的开发系统](../9-development-system/index.md) 收束成项目模板。
